= Basic Testing with AxonTestFixture
[[basic_testing]]
:navtitle: Basic Testing

The `AxonTestFixture` is the main tool for testing Axon applications.
It provides a fluent API for setting up test scenarios, executing actions, and verifying results using a clear Given-When-Then pattern.

`AxonTestFixture` is built on the same `ApplicationConfigurer` you use in production, which means:

* **No duplicate configuration** - Your tests use the same setup as your production code.
* **Integration testing support** - Test with real infrastructure (event stores, processors, etc).
* **Consistent behavior** - What works in tests works in production.

This makes the `AxonTestFixture` **the** choice whenever you want to test components that are attached to Axon.

When using Spring Boot, the configurer is created by the Axon's Spring Boot integration.
Inject it as a bean into your test for realistic integration testing:

[source,java,role=pseudocode]
----
import org.axonframework.common.configuration.ApplicationConfigurer;
import org.axonframework.test.fixture.AxonTestFixture;
import io.axoniq.framework.testcontainer.AxonServerContainer;
import org.junit.jupiter.api.*;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.testcontainers.service.connection.ServiceConnection;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

@SpringBootTest
@Testcontainers
class AccountTest {

    @Container
    @ServiceConnection
    static AxonServerContainer axonServer = new AxonServerContainer();

    @Autowired
    private ApplicationConfigurer configurer;

    private AxonTestFixture fixture;

    @BeforeEach
    void setUp() {
        fixture = AxonTestFixture.with(configurer);
    }

    @AfterEach
    void tearDown() {
        fixture.stop();
    }
    // Tests ...
}
----

The `@SpringBootTest` annotation ensures Spring Boot starts with your production configuration, and `@Autowired` injects the configurer bean created by Axon's Spring Boot integration.
The `AxonServerContainer` starts an Axon Server instance in a Docker container for realistic integration testing.
The `@ServiceConnection` annotation (Spring Boot 3.1+) automatically configures the Axon Server connection.

[#test_phases]
== Test phases

Every test follows a three-phase structure:

1. **<<given_phase,Given>>** - Set up initial state for your test.
2. **<<when_phase,When>>** - Execute the action being tested.
3. **<<then_phase,Then>>** - Verify the results of the action.

The API enforces this structure with type-safe phase transitions.

[#given_phase]
=== Given-phase: Setting up initial state

The given-phase defines the state before your test action.
Each operation runs in its own processing context and is immediately committed.

[#junit_extension]
== JUnit `AxonFrameworkExtension`

If you use JUnit for testing, you can simplify the lifecycle management of the `AxonTestFixture` by using the `AxonFrameworkExtension`.
This extension automatically creates and stops the fixture for you, so you do not have to worry about that in your tests.

To use the extension, simply annotate your test class with `@ExtendWith(AxonFrameworkExtension.class)` and declare a `AxonTestFixture` field in your test class. The extension will automatically inject the fixture into your test class and manage its lifecycle.

[source,java]
----
include::example$testing/basictesting/extension/basic/BasicExtensionUsage.java[tag=junit-extension-basic,indent=0]
----

<1> The `@ExtendWith(AxonFrameworkExtension.class)` annotation tells JUnit to use the `AxonFrameworkExtension` for this test.
<2> The `@ProvidedAxonTestFixture` annotation indicates that the `provider` field can create a new instance of an  `AxonTestFixture` for every test run.
<3> Use parameter injection to get the `AxonTestFixture` instance in your test method. The extension will automatically create and inject the fixture for you, so you can focus on writing your tests without worrying about fixture lifecycle management.


IMPORTANT: `@ProvidedAxonTestFixture` cannot be applied on static fields, as this breaks the lifecycle contract of getting a new instance of the fixture on every test run. You can however use `@ProvidedAxonTestFixture` on static and non-static methods if you want.


Alternatively, you can also parameterize `@ProvidedAxonTestFixture` with a class value implementing the `AxonTestFixtureProvider` interface. By doing so, you can reuse the same provider across multiple test classes, or even share it across your entire test suite by using a common base class.
By using the `@ProvidedAxonTestFixture` directly on a test method, you can override the default configured on class level.

[source,java]
----
include::example$testing/basictesting/extension/providers/ProviderBasedExtensionUsage.java[tag=junit-extension-providers,indent=0]
----

<1> The `@ProvidedAxonTestFixture(GlobalFixtureProvider.class)` annotation tells the extension to use the `GlobalFixtureProvider` class to create new instances of the `AxonTestFixture` for every test run. This allows you to centralize your fixture configuration in one place and reuse it across multiple test classes.
<2> This test method will use the `GlobalFixtureProvider` to create the fixture instance, as it is the default provider configured at the class level.
<3> This test method will use the `SpecificFixtureProvider` to create the fixture instance.
