= Intercepting

Axon provides a notion of interceptors.
The Reactor gateways allow for similar interceptor logic, namely the `ReactorMessageDispatchInterceptor`.
It allows us to centrally define rules and filters that will be applied to the messages sent through the Reactor gateways.

NOTE: Interceptors will be applied in the order they have been registered.

== Reactor dispatch interceptors

The `ReactorMessageDispatchInterceptor` should be used to centrally apply rules and validations for outgoing messages.
It is the Reactor counterpart of the `MessageDispatchInterceptor`, with one important difference: it runs inside the Reactor subscription.
The Reactor `Context` is thus available to the interceptor, which enables integration with reactive context holders such as Spring Security's `ReactiveSecurityContextHolder`.

The interface is described as follows:

[source,java]
----
@FunctionalInterface
public interface ReactorMessageDispatchInterceptor<M extends Message> {

    Mono<?> interceptOnDispatch(M message,
                                @Nullable ProcessingContext context,
                                ReactorMessageDispatchInterceptorChain<M> chain);
}
----

An interceptor receives the `message` that is being dispatched, the active `ProcessingContext` (if any), and the remaining `chain`.
It continues the chain by calling `chain.proceed(message, context)`, optionally with an enriched message.
Not calling `proceed` discards the message.

An interceptor can be typed on `CommandMessage`, `EventMessage`, or `QueryMessage` to only apply to that type of message.
An interceptor typed on `Message` applies to all of them.
For an example that integrates with Spring Security, see xref:messaging-concepts:message-intercepting.adoc[Message interception].
