= Dispatching

The "Reactive Gateways" offer a reactive API wrapper around the command, query and event gateways.
Most of the operations are similar to those from the non-reactive gateways, simply replacing the `CompletableFuture` with either a `Mono` or `Flux`.

WARNING: Reactor doesn't allow `null` values in streams.
Any `null` value returned from the handler will be mapped to link:https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html#empty[`Mono#empty()`,window=_blank,role=external].

== Configuration

The `ReactorCommandGateway`, `ReactorQueryGateway`, and `ReactorEventGateway` are registered automatically when the `axon-reactor` artifact is on the classpath.
They delegate to the regular `CommandGateway`, `QueryGateway`, and `EventGateway` of your application.

In a Spring Boot application, the gateways are available as beans, as the examples on this page show.
In a plain Java application, retrieve a gateway from the `AxonConfiguration`:

[source,java]
----
include::example$extensions/reactor/dispatching/PlainJavaGatewayLookup.java[tag=plain-java-gateway,indent=0]
----

Every operation of the gateways is also available with a `ProcessingContext` parameter.
Provide it when you dispatch from within a message handler, to propagate correlation data from one message to another.
When dispatching from outside a handler, use the variants without the `ProcessingContext`.

== Reactor command gateway

This section describes the methods on the `ReactorCommandGateway`.

[[send]]
=== `send`

Sends the given command once the caller subscribes to the command result.
Returns immediately.

There are two variants:

* `send(command, resultType)` returns a `Mono<R>` with the command's result, converted to the given `resultType`.
* `send(command)` returns a `Mono<Void>` that completes once the command has been handled, regardless of its result.

A common pattern is using the REST API to send a command.
In this case it is recommended to, for example, use link:https://docs.spring.io/spring-framework/reference/web/webflux.html[WebFlux,window=_blank,role=external], and return the command result `Mono` directly to the controller:

[[querymany]]
=== `queryMany`

Sends the given `query`, expecting a list of `responseType` instances as the response.
The result is a `Mono` of that list, as shown in the controller above.

[[streamingquery]]
=== `streamingQuery`

Sends the given `query` as a streaming query, expecting the response to be streamed element by element.
The result is a `Flux` of `responseType` instances, as shown in the controller above.

[[subscriptionquery]]
=== `subscriptionQuery`

Sends the given `query` as a subscription query.
The resulting `Flux` first emits the initial result, and then keeps streaming incremental updates until the subscriber cancels its subscription.

Note that the initial result and the updates are both converted to the same `responseType`.
