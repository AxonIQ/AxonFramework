= Entity Inheritance
:navtitle: Entity inheritance

This page explains how Axon runs the event sourcing handlers declared on an entity class and its supertypes.
For a parent entity that owns child entities, see xref:commands:entities/entity-hierarchies.adoc[Entity hierarchies].

== How the handlers run

An overriding method counts as one handler; call `super` to run the overridden one.
Separate methods for the same event all run, parent handlers first, each receiving the entity returned by the previous one.
Within one class the order is unspecified.
If a handler returns an entity the next handler cannot run on, evolving fails with a `StateEvolvingException`.
Handlers of the returned type do not run for the same event.

A handler matches an event by its event name, so a handler accepting `Object` does not receive other events.

+

[source,java]

[source,text]

1. Course.countTouch           InitialCourse(0) -> InitialCourse(1)

----

A handler of a more general type that changes the concrete type to a sibling is rejected when a handler of the previous type follows, because that handler cannot run on the sibling.

[source,java]
----
include::example$commands/entities/eventsourcedentity/hierarchy/typechange/RejectedTypeChangeExample.java[tag=type-change-rejected,indent=0]
----

[source,text]
----
Deposited(10) on a VipPass with balance 0
1. Pass.onDeposit              VipPass(0) -> GiftPass(10)
2. VipPass.onVipDeposit        rejected: Axon throws a StateEvolvingException
----

Axon throws a `StateEvolvingException`.
Its cause names the handler that returned the new type, the next handler, and the type that handler requires.
